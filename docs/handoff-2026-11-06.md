## Коротко для следующего AI

Это существующий статический сайт с 11 играми, Firebase Authentication, Firestore и PeerJS.
Сначала получите актуальный GitHub и проверьте локальные изменения. Основной код — в `src/`.
Не начинайте повторную реализацию рейтингов: они уже опубликованы и проверены.

## Что означает «мобильная версия»

Это тот же сайт, открытый в браузере телефона, с адаптивным интерфейсом.
Отдельное нативное приложение, APK или iOS-приложение в этой работе не создавались.
На широком экране параллельные игры показаны сеткой, на узком — вкладками.
Мобильную раскладку проверяли в автоматизированном Edge/Chromium с узким viewport;
это не испытание на всех физических моделях телефонов и не полная проверка Safari/iOS.
В проекте уже есть PWA-манифест, service worker и установка сайта на главный экран.

## Что добавлено

- Основной рейтинг людей: отдельный для каждой из 11 игр, старт 1200, Glicko-1.
  Первые 10 партий предварительные (`?`). Разные варианты и контроли времени одной игры
  используют общий рейтинг. Это собственные настройки, не точная копия Chess.com.
- Рейтинг меняется только в онлайне между разными аккаунтами после согласия всех участников.
  Ходы и доступные часы ждут подтверждения рейтингового старта.
  Боты, локальная игра, анализ, продолжение с позиции и подсказки основной рейтинг не меняют.
- У ботов показана ориентировочная сила `≈`. Она не калибрована по людям;
  массовые тренировочные матчи ботов в этой работе не проводились.
- На главной — «Мои результаты»: личные рейтинги, лидеры и последние 20 результатов.
- В общей комнате можно одновременно играть в 3 или 4 разные игры из списка:
  точки (`tochki`), крестики-нолики (`ttt`), го (`go`), шашки (`checkers`),
  морской бой (`battleship`), Коридор (`quoridor`), Лава (`lava`). Шахмат в этом наборе нет.
- Набор и рейтинговый режим принимаются вторым игроком. Доски и сетевые каналы независимы.
  Скрытые вкладки продолжают работать. В Лаве и Дураке отдельного адаптера часов пока нет.
- За победу на доске 1 очко, ничью 0.5, поражение 0. Общий результат — после всех досок.
  Связки имеют отдельные рейтинги `multi3` и `multi4`; рейтинги отдельных игр не меняются.
- В играх на 3–4 человек рейтинг рассчитывается по попарным местам.
  Если один участник сдался, а оставшиеся договорились о ничьей, сдавшийся остаётся проигравшим.

## Облако и важные инварианты

Firebase project: `mdgames153`. Firestore `(default)`, Standard edition,
`europe-west3` (Франкфурт), free tier; защита удаления базы включена.
Реализация опубликована на Firebase Hosting. Правила выпущены, индекс истории достиг READY.
Аккаунты находятся в Authentication; рейтинги сохраняются при обычном обновлении кода.

Коллекции:

- `ratingProfiles/{uid}` — имя, updatedAt; email в рейтинг не записывается.
- `ratingPools/{pool}/players/{uid}` — v, r, rd, games, wins, draws, losses, lastMatch, updatedAt.
  Пулы: chess, checkers, go, ttt, tochki, battleship, lava, abalone, falling4, quoridor,
  durak, multi3, multi4. Начало r=120000, rd=35000; первые 10 игр предварительные.
- `ratedMatches/{id}` — участники, имена, конфигурация, согласия, неизменяемые отчёты,
  статус waiting/playing/settled/cancelled и изменения рейтингов.
- `ratedMatches/{id}/checks/{uid}` — проверенные базовые снимки и вычисленные значения.

Каждый клиент подтверждает только своё согласие и свой результат. Все отчёты должны совпасть.
Проверочные документы записываются ОТДЕЛЬНЫМИ запросами (не общим writeBatch), чтобы уложиться
в лимит выражений правил для 4 игроков. Затем все рейтинги и итог партии меняются атомарно.
Старые проверки нельзя использовать после изменения базовых рейтингов. Повторный зачёт запрещён.

Не удаляйте обработку конфликтов accept/report: одновременные записи могли давать permission-denied
до сообщения о конфликте транзакции. Исправление пишет только собственное поле и ограниченно
повторяет запрос, если сервер подтвердил продвижение той же партии. Реальные отказы не скрываются.
Не удаляйте ожидание joining перед выбором «без рейтинга», отмену waiting-заявок и фильтр
hasPendingWrites с includeMetadataChanges: иначе возможны гонки согласия и преждевременные статусы.
В интерфейсе таблиц есть защита от перезаписи новой вкладки запоздавшим ответом старого запроса.

## Ограничения

Ходы остаются в PeerJS, отдельного авторитетного сервера ходов и античита нет.
Все участники должны отправить совпадающий результат; выход или отказ одного может оставить
партию без зачёта. Автоматического поражения за отключение в этой версии нет.
Перезагрузка хозяина может прервать комнату. Glicko пока не повышает RD за период неактивности.
Это важно учитывать при дальнейшей разработке; не ослабляйте правила базы ради обхода ошибок.

## Запуск на компьютере друга

Нужны Git, Node.js с npm (в этой работе использован Node 24), Python 3 с zoneinfo,
для эмулятора — Java 21+. Браузерные тесты используют установленный Microsoft Edge (`msedge`).
На Windows при ошибке часовых поясов Python установите `python -m pip install tzdata`.

Если репозитория ещё нет:

```sh
git clone https://github.com/maximdibrova-netizen/TicTacToe.git
cd TicTacToe
npm ci
npm run build
python -m http.server 8000
```

Открыть http://localhost:8000/ . Для существующей копии сначала `git status`, затем,
при чистом рабочем дереве, `git pull --rebase origin main`. Сохраните свою незавершённую работу
перед pull. На GitHub может появиться более новый код — не откатывайте его к этому снимку.

Порты эмуляторов: Auth 9099, Firestore 8080. Тесты используют demo-проекты и локальные PeerJS-серверы.
Не запускайте несколько копий одного браузерного теста одновременно: порты фиксированы.

http://localhost:8000/?authEmulator=9099&firestoreEmulator=8080 .
Эти параметры действуют только на loopback. Основной сайт всегда использует настоящее облако.
Auth-only проверка не обращается к production Firestore.

## Публикация и совместная работа

Друг входит в Firebase CLI СО СВОИМ Google-аккаунтом, получив доступ к проекту:

```sh
firebase login
firebase projects:list
npm run deploy:firebase
```

Команда запускает prepare_firebase.py и `firebase deploy --only hosting,firestore --project mdgames153`.
Проверки не запускаются ею автоматически: выполните их заранее.
Публикуется whitelist в firebase-public, правила и индексы. Не публикуйте корень репозитория.
Обновление кода не сбрасывает аккаунты/рейтинги; смена модели требует согласованной миграции.
Индексы могут несколько минут создаваться; проверка: `firebase firestore:indexes --pretty --project mdgames153`.

Для сохранения работы получите свежую main, внесите исходники, соберите, проверьте, затем
сделайте commit и обычный push. Force push не используйте. Согласуйте, кто в данный момент публикует.
Push сохраняет код в GitHub и обновляет настроенное зеркало GitHub Pages;
Firebase обновляется отдельной командой. Для изменения только документации сборка сайта не требуется.
